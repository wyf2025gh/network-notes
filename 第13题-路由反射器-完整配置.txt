  本题不是新建拓扑，而是在第 12 题那套"日"字形网络上做减法：
  把 AS 65001 内 3 条 iBGP 减成 2 条，靠 AR1 做反射器，
  让 AR3 在失去自己上行链路的情况下，仍从 AR2 那边拿到
  192.168.2.0/24。

  本文数据全部来自设备实时回显（display 命令原始输出），
  不是按方案推演写的。

【三、本题要改的四步】
================================================================

  第 1 步  AR1 升级为反射器
  --------------------------------------------------------------

    system-view
    bgp 65001
     ipv4-family unicast
      peer 2.2.2.2 reflect-client
      peer 3.3.3.3 reflect-client

  要点：
    - reflect-client 只配在【反射器】上，client 侧一个字都不用加
    - 必须在 ipv4-family unicast 视图里，不在 bgp 进程视图
    - 配反了（配到 AR2/AR3 上）邻居不会断，但反射不工作，
      设备也不报错 —— 属于"静默失效"


  第 2 步  拆掉 AR2 <-> AR3 之间的 iBGP
  --------------------------------------------------------------

    AR2:  bgp 65001
           ipv4-family unicast
            undo peer 3.3.3.3 enable
           undo peer 3.3.3.3

    AR3:  bgp 65001
           ipv4-family unicast
            undo peer 2.2.2.2 enable
           undo peer 2.2.2.2

  要点：
    - undo peer 会连带清掉那条上的 enable 和 next-hop-local，
      这是预期内的，不用去补
    - AR2、AR3 各自变成只剩 1 个 iBGP 邻居（都是 1.1.1.1）
    - 邻居总数：2 条 iBGP + 2 条 eBGP = 4 条


  第 3 步  【关键】先做一次"假通过"检查
  --------------------------------------------------------------

    此时直接去 AR3 上看：

      display bgp routing-table 192.168.2.0

    会看到有这条路由，而且 best。
    但这跟反射器一点关系都没有 ——
    AR3 自己有一条直连 AR4 的 eBGP，它本来就能学到。

    分辨方法：看有没有 Originator 字段。
      自己 eBGP 学来的：没有 Originator，Direct Out-interface 有值
      反射器转过来的：有 Originator，下一跳是别人的环回地址

    本题 AR3 的直连 eBGP 必须拿掉，否则永远测不出反射。


  第 4 步  掐掉 AR3 的上行（可逆动作）
  --------------------------------------------------------------

    interface GigabitEthernet0/0/1
     shutdown

    用 shutdown 而不是 undo peer，因为一会儿还要恢复。

    效果：
      AR3 侧  GE0/0/1 -> *down，eBGP 邻居 10.0.34.4 -> Idle
      AR3 自己那条 192.168.2.0/24（MED 100）随之消失
      AR4 侧  peer 10.0.34.3 -> Idle

    这时候 AR3 手上【还有没有】这条路，才是本题的答案。

    等 30 秒左右（eBGP 断开立刻感知，但要等 AR2 重新选路
    并把路由推过来），然后再看。

    收尾：undo shutdown 恢复，观察回切。

【四、设备最终配置（从设备读回，可直接对照）】
================================================================

  ---- AR1（反射器）-------------------------------------------

    bgp 65001
     router-id 1.1.1.1
     peer 2.2.2.2 as-number 65001
     peer 2.2.2.2 connect-interface LoopBack0
     peer 3.3.3.3 as-number 65001
     peer 3.3.3.3 connect-interface LoopBack0
     ipv4-family unicast
      undo synchronization
      network 192.168.1.0
      peer 2.2.2.2 enable
      peer 2.2.2.2 reflect-client
      peer 3.3.3.3 enable
      peer 3.3.3.3 reflect-client

  说明：
    - 没有配 reflector cluster-id，默认取 Router ID 1.1.1.1，
      所以 Cluster list 显示的就是 1.1.1.1
    - AR1 没配 next-hop-local。这不是漏了：
      反射时不改下一跳，AR3 拿到的下一跳是 2.2.2.2，
      OSPF 能查到，正好可用（详见第七节第 3 条）


  ---- AR2（client + 出口 1）-----------------------------------

    bgp 65001
     router-id 2.2.2.2
     peer 1.1.1.1 as-number 65001
     peer 1.1.1.1 connect-interface LoopBack0
     peer 10.0.24.4 as-number 65002
     ipv4-family unicast
      undo synchronization
      peer 1.1.1.1 enable
      peer 1.1.1.1 next-hop-local
      peer 10.0.24.4 enable

  说明：
    - 与 AR3 的 peer 已删除
    - next-hop-local 保留在 1.1.1.1 上，必须留：
      它发给 AR1 的路由下一跳写成 2.2.2.2，
      AR1 再反射给 AR3 时下一跳原样是 2.2.2.2，
      AR3 才能用 OSPF 解析出来


  ---- AR3（client + 出口 2）-----------------------------------

    bgp 65001
     router-id 3.3.3.3
     peer 1.1.1.1 as-number 65001
     peer 1.1.1.1 connect-interface LoopBack0
     peer 10.0.34.4 as-number 65002
     ipv4-family unicast
      undo synchronization
      peer 1.1.1.1 enable
      peer 1.1.1.1 next-hop-local
      peer 10.0.34.4 enable

  说明：
    - 与 AR2 的 peer 已删除
    - peer 1.1.1.1 next-hop-local 现在已无作用
      （AR3 没有别的 iBGP 邻居了），留着无害，删掉也行


  ---- AR4（与第 12 题相同，未改动）----------------------------

    bgp 65002
     router-id 4.4.4.4
     peer 10.0.24.2 as-number 65001
     peer 10.0.34.3 as-number 65001
     ipv4-family unicast
      undo synchronization
      network 192.168.2.0
      peer 10.0.24.2 enable
      peer 10.0.24.2 route-policy ABC export
      peer 10.0.34.3 enable
      peer 10.0.34.3 route-policy CDE export

    route-policy ABC permit node 10
     apply cost 200
    route-policy CDE permit node 10
     apply cost 100

  说明：
    - ABC / CDE 这两个策略名必须与定义完全一致。
      第 12 题曾把引用写成 BCD、定义写成 CD，
      差一个字母，策略静默失效，MED 保持默认 0

================================================================

  5.1  AR3 上（GiG0/0/1 已 shutdown 时）
  --------------------------------------------------------------

    <AR3> display bgp peer

      Total number of peers : 2   Peers in established state : 1
      1.1.1.1      65001  ...  Established
      10.0.34.4    65002  ...  Idle

  只剩一个邻居，而且是自己上行那条挂了。这就是"孤立"状态。


    <AR3> display bgp routing-table 192.168.2.0

      Paths:   1 available, 1 best, 1 select
      From: 1.1.1.1 (1.1.1.1)
      Relay IP Nexthop: 10.0.23.2
      Relay IP Out-Interface: GigabitEthernet0/0/2
      Original nexthop: 2.2.2.2
      AS-path 65002, origin igp, MED 200, localpref 100,
              valid, internal, best, select, active, pre 255, IGP cost 1
      Originator:  2.2.2.2
      Cluster list: 1.1.1.1

  七个看点，逐个对：

    +--------------------+---------------------------+------------------+
    | 看点               | 实测                      | 说明             |
    +--------------------+---------------------------+------------------+
    | 路由还在不在       | 1 available, 1 best       | 上行断了还活着   |
    | 谁给的             | From 1.1.1.1              | 只有反射器能给   |
    | Originator         | 2.2.2.2                   | 源头是 AR2       |
    | Cluster list       | 1.1.1.1                   | AR1 的 cluster-id|
    | AS_PATH            | 65002，长度 1             | RR 不加 AS 号    |
    | 下一跳             | 2.2.2.2 -> 10.0.23.2      | OSPF 递归解析    |
    | 出接口             | GE0/0/2                   | 走 10.0.23.0/24  |
    +--------------------+---------------------------+------------------+

  Originator 是本题最硬的证据：
  2.2.2.2 是 AR2 的 Router ID，说明这条路由是 AR2 从 AR4 学到、
  带进 iBGP，再由 AR1 反射过来的。和 AR3 自己那条 eBGP 毫无关系。


    <AR3> display ip routing-table 192.168.2.0

      Destination/Mask   Proto  Pre  Cost   Flags  NextHop    Interface
      192.168.2.0/24     IBGP   255  200    RD     2.2.2.2    GE0/0/2

  进了 FIB，Proto 是 IBGP（不是 BGP，因为是从 iBGP 邻居学的），
  Cost 列 200 就是 MED 的值 —— 华为把 MED 借这个位置显示。


  5.2  AR1 上（反射器视角）
  --------------------------------------------------------------

    <AR1> display bgp routing-table 192.168.2.0

      RR-client route.
      From: 2.2.2.2 (2.2.2.2)
      Relay IP Nexthop: 10.0.12.2
      Original nexthop: 2.2.2.2
      AS-path 65002, origin igp, MED 200, ... internal, best
      Advertised to such 2 peers:
         2.2.2.2
         3.3.3.3

  关键两行：

    RR-client route.        只有"从 client 学来"的路由才有这个标记，
                            它是反射器在干活的直接证据
    Advertised to 2 peers   两个都是 client，说明这条路由被复制给了
                            另一个 client（2.2.2.2 与 3.3.3.3 各自都收）


  5.3  AR2 上（另一侧 client）
  --------------------------------------------------------------

    <AR2> display bgp routing-table 192.168.2.0

      From: 10.0.24.4 (4.4.4.4)
      Direct Out-interface: GigabitEthernet0/0/1
      AS-path 65002, MED 200, ... external, best
      Advertised to such 1 peers:
         1.1.1.1

  AR2 此刻只有 1 条路径：AR3 的上行断了、AR2 与 AR3 的 iBGP
  也早被拆掉，它只剩自己从 AR4 学到的那条（MED 200），
  所以它是 best，并只向 AR1 通告。


  5.4  端到端
  --------------------------------------------------------------

    <AR1> ping -a 192.168.1.254 -c 4 192.168.2.10

      4 packet(s) transmitted, 3 packet(s) received, 25.00% packet loss
      Reply from 192.168.2.10: bytes=56 ttl=126 time=30 ms

  ttl 126 = 128 - 2：AR1 自己发出，被 AR2、AR4 各转发一次。

  首包 Request time out 是 ARP 没缓存，不是配置问题。


  5.5  恢复后的连锁反应（undo shutdown 之后实测）
  --------------------------------------------------------------

  恢复 GE0/0/1 后，三台的状态是这样（这是实测，不是推演）：

    AR3：1 available, 1 best
         From: 10.0.34.4    MED 100    external, best
         Direct Out-interface: GE0/0/1
         -> 自己那条 eBGP 回来了，MED 100 比反射来的 200 更优

    AR1：1 available, 1 best
         RR-client route.
         From: 3.3.3.3      MED 100
         Advertised to such 2 peers: 2.2.2.2 / 3.3.3.3
         -> AR1 的 best 换成了 AR3 那条（MED 100 胜 200）

    AR2：2 available, 1 best
         From: 1.1.1.1（反射来的）MED 100, Originator 3.3.3.3,
              Cluster list 1.1.1.1, best
         From: 10.0.24.4（自己 eBGP）MED 200,
              "not preferred for MED"

  为什么 AR3 只剩 1 条？链条是这样走的：

    1. AR3 接口恢复 -> 自己学到 MED 100 的 eBGP 路由，成为 best
    2. AR3 把 best 通告给 AR1（client 发给 RR，允许）
    3. AR1 收到 MED 100，比原来 AR2 的 MED 200 更优 -> best 换成 AR3
    4. AR1 的 best 来自 AR3 本身 -> 不会再反射回 AR3
       （iBGP 不向来源邻居回传）
    5. AR3 那条反射路由被隐式撤销 -> 只剩 1 条

  这和"第 12 题里 Local_Pref=200 让 AR2 闭嘴"是同一种现象：
  【改了上游的一个值，下游看到的路径数量会变】。
  真实网络里改一条 MED 能让半个 AS 重新选路，就是这个道理。

【六、踩坑记录】
================================================================

  1. 假通过：AR3 自带 eBGP，不掐上行测不出反射
  --------------------------------------------------------------
     AR2 和 AR3 都是 ASBR，各自连 AR4。所以 192.168.2.0/24
     两边都能直接学到。只拆 iBGP 不看来源，路由照样在、
     ping 照样通，但反射器根本没被验证。
     判据：有没有 Originator 字段 + 下一跳是直连还是环回。

  2. reflect-client 配在 client 上，静默失效
  --------------------------------------------------------------
     只该配在 RR 上。配反了邻居不断、不报错，只是反射不工作。
     验证方法：RR 上 display bgp routing-table 看有没有
     "RR-client route." 这一行。

  3. 反射器不改下一跳，AR3 可能 0 best
  --------------------------------------------------------------
     RR 只搬路由，下一跳原样保留。本题 AR3 拿到的下一跳是
     2.2.2.2，靠 OSPF 才解析得出来。
     如果 AR3 显示 0 best，第一件事查：
       display ip routing-table 2.2.2.2
     本题实测：2.2.2.2/32  OSPF  10  cost 1  ->  10.0.23.2  GE0/0/2

  4. 以为 AS_PATH 应该变长
  --------------------------------------------------------------
     OSPF 多区域时 ABR 会重新生成 Type-3 LSA，
     IS-IS 的 L2 明细会下发给 L1（除了 ATT 那条默认路由）。
     但 BGP 的 RR 反射【不加 AS 号、不改 AS_PATH】。
     判断 RR 是否生效，看 Originator 和 Advertised 计数，
     不看 AS_PATH。

  5. route-policy 名字与定义不一致（第 12 题遗留）
  --------------------------------------------------------------
     AR4 上引用写成 route-policy BCD export，
     定义却是 route-policy CD permit node 10。
     差一个字母，策略静默失效，MED 保持默认 0。
     本次已统一为 ABC / CDE，定义与引用一致。

  6. 用 undo peer 代替 shutdown
  --------------------------------------------------------------
     undo peer 会把 enable、next-hop-local 一起清掉，
     恢复时要重配三条。本题只需要"暂时断一下"，
     用 shutdown 接口，undo shutdown 就全回来了。

  7. 恢复后以为应该变成 2 条
  --------------------------------------------------------------
     实际只有 1 条（原因见 5.5 五步链条）。
     不是配错，是 iBGP 不向来源邻居回传导致的隐式撤销。

  8. 把 "Advertised to such N peers" 当成实时状态
  --------------------------------------------------------------
     这个字段是入表时算出来的候选列表，会包含"理论上该发"的
     邻居。真正验证要对比对端的 PrefRcv / 路径数，
     不要只信这一行。


================================================================
【七、设计点说明】
================================================================

  1. iBGP 水平分割的代价
  --------------------------------------------------------------
     从 iBGP 邻居学来的路由，不再转发给其他 iBGP 邻居。
     这条规则防了环，但要求 AS 内 iBGP 必须【全互联】：
     3 台 3 条，10 台 45 条，100 台 4950 条。
     公式  n(n-1)/2

  2. RR 做的事情只有一件
  --------------------------------------------------------------
     把"从 client 学到的路由"再发给其他 client。
     水平分割没有被取消，只是对 client 开了一个例外。
     RR 自己不是 client，client 也不需要知道谁是 RR。

  3. RR 不改下一跳，这是设计而不是缺陷
  --------------------------------------------------------------
     如果 RR 每跳都改下一跳，流量会在 AS 内部绕一次远路。
     所以 RR 只搬路由。
     代价是：下一跳必须能被 client 解析 ——
     要么下一跳本身在直连网段，要么 AS 内跑 IGP。
     本题能通，全靠第 12 题配的 OSPF。

  4. 两个防环字段
  --------------------------------------------------------------
     Originator ID  路由最初进入 iBGP 的那台路由器的 Router ID。
                    收到时若等于自己的 Router ID，直接丢弃。
                    -> 防"还给我"

     Cluster list   每经过一个 cluster，就往里压一个 cluster-id。
                    收到时若发现自己的 cluster-id 已在里面，丢弃。
                    -> 防"几个反射器之间转圈"

     本题实测：AR3 收到 Originator 2.2.2.2、Cluster list 1.1.1.1

  5. cluster-id 默认值
  --------------------------------------------------------------
     不配 reflector cluster-id 时，取本机 Router ID。
     所以 AR1 的 Cluster list 是 1.1.1.1。
     多台 RR 做主备时，同一 cluster 内的 RR 必须配成【相同】
     cluster-id，否则防环判断会失效。

  6. RR 的中心节点风险（本题思考题 3 的落点）
  --------------------------------------------------------------
     AR1 挂了：AR2 照样通（本地 eBGP 学来的，不依赖 AR1）
               AR3 直接断（唯一来源是反射，反射器没了就没了）
     所以真实网络里 RR 一定成对部署，两台互为备份，
     分别放在不同 cluster-id 下，client 同时连两台。

  7. 与第 11 题 next-hop-local 的关系
  --------------------------------------------------------------
     第 11 题是链式拓扑，iBGP 只有一跳，问题在"下一跳跨 AS"。
     本题是星形拓扑，问题在"下一跳能不能解析"。
     手段是同一个：让下一跳变成 AS 内可达的地址。
     第 11 题靠 next-hop-local，本题靠 OSPF 覆盖环回。
     两条路都行，本质都是"给下一跳找一条内部路"。

【八、思考题答案】
================================================================

  1. 全互联要几条 iBGP？
  --------------------------------------------------------------
     公式 n(n-1)/2
       3 台 -> 3 条
       5 台 -> 10 条
      10 台 -> 45 条
     100 台 -> 4950 条
     改为 RR 后，100 台只需 99 条（每个 client 一条）。

  2. 两个字段分别拦什么？
  --------------------------------------------------------------
     Originator ID  拦"路由绕回最初的产生者"。
                    判据：收到的 Originator == 自己的 Router ID
     Cluster list   拦"路由在多个 cluster 之间转圈"。
                    判据：list 里已有自己的 cluster-id
     一句话：Originator 管"别还给我"，Cluster list 管"别绕圈"。
     单 RR 单 cluster 时主要靠前者，多 RR 组网主要靠后者。

  3. 10.0.23.0/24 还有用吗？AR1 挂了会怎样？
  --------------------------------------------------------------
     有用，而且是关键路径。AR3 那条反射路由的下一跳是 2.2.2.2，
     到 2.2.2.2 的路只有 10.0.23.0/24 这一条（OSPF）。
     这条线一断，AR3 立刻 0 best。

     AR1 挂掉：
       AR2  照样有 192.168.2.0/24（本地 eBGP 来源，不依赖 AR1）
       AR3  失去该路由（唯一来源是反射；自己上行又关着）
     两者结果不同，正好说明 RR 是单点。
