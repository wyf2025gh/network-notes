【一、拓扑速览】

             AS 65001                    AS 65002
  +-------------------------+   +-------------------------+
  |                         |   |                         |
 PC1 ---- AR1 ---- AR2  ═══════  AR3 ---- AR4 ---- PC2
  |        iBGP             eBGP            iBGP        |
  +-------------------------+   +-------------------------+

  是一条链，不是环形。没有等价路径，选路不用纠结。

  设备角色：

  AR1  AS 65001 内部，纯 iBGP，业务网段从它始发
  AR2  AS 65001 边界，对内 iBGP、对外 eBGP（本题主角）
  AR3  AS 65002 边界，对内 iBGP、对外 eBGP
  AR4  AS 65002 内部，纯 iBGP，业务网段从它始发

  连接表（5 根线，全程 Copper）：

  +------+-------------------+-------------------+---------------+
  | 序号 | A 端              | B 端              | 承载网段      |
  +------+-------------------+-------------------+---------------+
  |  1   | PC1 Ethernet0/0/1 | AR1 GE0/0/0       | 192.168.1.0   |
  |  2   | AR1 GE0/0/1       | AR2 GE0/0/0       | 10.0.12.0     |
  |  3   | AR2 GE0/0/1       | AR3 GE0/0/0       | 10.0.23.0     |
  |  4   | AR3 GE0/0/1       | AR4 GE0/0/0       | 10.0.34.0     |
  |  5   | AR4 GE0/0/1       | PC2 Ethernet0/0/1 | 192.168.2.0   |
  +------+-------------------+-------------------+---------------+

  第 3 根线就是 AS 边界。它左边的接口属于 65001，右边的属于 65002。

  | AR4  | GE0/0/1   | 192.168.2.254/24  | PC2 网关       |
  +------+-----------+-------------------+----------------+

  BGP 身份规划：

  +------+----------------+-------------+-------------------------+
  | 设备 | Router ID      | Local AS    | 邻居（全部单跳直连）    |
  +------+----------------+-------------+-------------------------+
  | AR1  | 1.1.1.1        | 65001       | 10.0.12.2  iBGP         |
  | AR2  | 2.2.2.2        | 65001       | 10.0.12.1  iBGP         |
  |      |                |             | 10.0.23.3  eBGP         |
  | AR3  | 3.3.3.3        | 65002       | 10.0.23.2  eBGP         |
  |      |                |             | 10.0.34.4  iBGP         |
  | AR4  | 4.4.4.4        | 65002       | 10.0.34.3  iBGP         |
  +------+----------------+-------------+-------------------------+

  三条邻居关系，不是四条。AR1 和 AR3 之间没有邻居，它们隔着一个 AS。

  Router ID 必须四台互不相同。相同会导致邻居无法建立（eBGP 尤其
  严格），这是排错时第一个要看的。

  AS 号：65001 / 65002 都在私有段 64512-65534 内，实验室随便用。

【四、设备配置】
================================================================

  顺序很重要：先把接口和直连 ping 全打通，再起 BGP。
  BGP 邻居要建立在"到对端地址可达"的基础上，底层不通怎么调试
  都是白搭。

----------------------------------------------------------------
  AR1（AS 65001 内部，业务网段始发点）
----------------------------------------------------------------

system-view
sysname AR1

interface GigabitEthernet0/0/0
 ip address 192.168.1.254 24
quit

interface GigabitEthernet0/0/1
 ip address 10.0.12.1 24
quit

bgp 65001
 router-id 1.1.1.1
 peer 10.0.12.2 as-number 65001
 ipv4-family unicast
  network 192.168.1.0 255.255.255.0
  peer 10.0.12.2 enable
 quit
quit

save

  network 只写网络号（network 192.168.1.0）也能生效，VRP 会按自然
  掩码 /24 补全。但写全掩码更保险：一旦以后网段改成 /25 /26，
  只写网络号就会宣布错，而且不报错。

  ipv4-family unicast 视图下必须再 enable 一次邻居。新版本 VRP
  这一步是必须的，漏了邻居一直是 Idle。


----------------------------------------------------------------
  AR2（AS 65001 边界，本题重点设备）
----------------------------------------------------------------

system-view
sysname AR2

interface GigabitEthernet0/0/0
 ip address 10.0.12.2 24
quit

interface GigabitEthernet0/0/1
 ip address 10.0.23.2 24
quit

bgp 65001
 router-id 2.2.2.2
 peer 10.0.12.1 as-number 65001
 peer 10.0.23.3 as-number 65002
 ipv4-family unicast
  peer 10.0.12.1 enable
  peer 10.0.12.1 next-hop-local
  peer 10.0.23.3 enable
 quit
quit

save

  next-hop-local 只加在 iBGP 邻居（10.0.12.1）后面，不加在 eBGP
  邻居后面。这句是本题的核心，漏了 AR1 就是 0 best，详见第六节坑 1。

  AR2 自己不宣告任何网段。它只是把 AR1 的路由往外送、把 AR3 的
  路由往里送，转手而已。


----------------------------------------------------------------
  AR3（AS 65002 边界，和 AR2 镜像对称）
----------------------------------------------------------------

system-view
sysname AR3

interface GigabitEthernet0/0/0
 ip address 10.0.23.3 24
quit

interface GigabitEthernet0/0/1
 ip address 10.0.34.3 24
quit

bgp 65002
 router-id 3.3.3.3
 peer 10.0.23.2 as-number 65001
 peer 10.0.34.4 as-number 65002
 ipv4-family unicast
  peer 10.0.23.2 enable
  peer 10.0.34.4 enable
  peer 10.0.34.4 next-hop-local
 quit
quit

save

  注意方向：next-hop-local 永远加在"发给 iBGP 邻居"的那一条上。
  AR3 的 iBGP 邻居是 10.0.34.4（AR4），不是 10.0.23.2。


----------------------------------------------------------------
  AR4（AS 65002 内部，业务网段始发点）
----------------------------------------------------------------

【五、验证命令】
================================================================

  ① 三条邻居是否建立
  --------------------------------------------------------------
  在任意一台：display bgp peer

    合计 3 条，State 全部 Established：
      AR1 上 1 条（10.0.12.2）
      AR2 上 2 条（10.0.12.1 和 10.0.23.3）
      AR3 上 2 条（10.0.23.2 和 10.0.34.4）
      AR4 上 1 条（10.0.34.3）

    State 是 Active 或 Connect，说明 TCP 179 没建起来，看第六节坑 4。
    State 是 Idle，八成是 ipv4-family 里忘了 peer enable。

  ② 三个视角看同一条路由（本题核心）
  --------------------------------------------------------------
  在 AR2：display bgp routing-table 192.168.2.0
    From: 10.0.23.3，Original nexthop: 10.0.23.3
    AS-path 65002，标记 external（eBGP 学来的）
    Advertised to such 1 peers: 10.0.12.1

  在 AR1：display bgp routing-table 192.168.2.0
    修复后 Original nexthop: 10.0.12.2（被 AR2 改写了）
    AS-path 65002，标记 internal（iBGP 学来的）
    Paths: 1 available, 1 best, 1 selected

  在 AR4：display bgp routing-table 192.168.1.0
    Original nexthop: 10.0.34.3（被 AR3 改写了）
    AS-path 65001，标记 internal

  在 AR2：display bgp routing-table 192.168.1.0
    Original nexthop: 10.0.12.1
    AS-path Nil —— 本地始发的路由还没加 AS 号
    external / internal 的区别，就是 eBGP 邻居和 iBGP 邻居的区别。

  ③ 修复前后的关键对比（本题的判据都在这）
  --------------------------------------------------------------
  修复前 AR1 上：

    Paths:   1 available, 0 best, 0 selected
    Relay IP Nexthop: 0.0.0.0
    Relay IP Out-interface: （空）
    Original nexthop: 10.0.23.3

  修复后 AR1 上：

    Paths:   1 available, 1 best, 1 selected
    Relay IP Nexthop: 0.0.0.0
    Relay IP Out-interface: GigabitEthernet0/0/1
    Original nexthop: 10.0.12.2

  两次都是 0.0.0.0，含义完全不同。分辨方法：
    Relay Nexthop 0.0.0.0 + Out-interface 有值  = 下一跳直连，无需递归
    Relay Nexthop 0.0.0.0 + Out-interface 空    = 递归失败，路由作废
  只看 0.0.0.0 会误判，必须看 Out-interface 和 best 计数。

  ④ 路由是否进了转发平面
  --------------------------------------------------------------
  在 AR1：display ip routing-table 192.168.2.0
    期望 192.168.2.0/24  IBGP  255  -> 10.0.12.2
  在 AR4：display ip routing-table 192.168.1.0
    期望 192.168.1.0/24  IBGP  255  -> 10.0.34.3

  优先级 255 是 BGP 的正常值，比直连、静态、OSPF 都低，不是配错。

  ⑤ 端到端
  --------------------------------------------------------------
  PC1：ping 192.168.2.10
    期望 5/5，ttl = 124（128 - 4，四台路由器转发）

  AR1：ping -a 192.168.1.254 -c 4 192.168.2.10
    期望 ttl = 125（源设备自己不算一跳）

  首包超时属正常（ARP + BGP 首次收敛）。

【六、本题实测踩坑记录】
================================================================

  坑 1：iBGP 不改下一跳，AR1 上 0 best（本题唯一真正的坑）
  --------------------------------------------------------------
  现象：三条邻居全 Established，AR2 上 192.168.2.0/24 明明是
        valid/best/selected，AR1 上却是 1 available / 0 best /
        0 selected，display ip routing-table 里查不到，ping 不通。
  真相：AR2 从 eBGP 学到这条路由时，下一跳是 10.0.23.3（AR3 把
        下一跳改成了自己）。AR2 转发给 iBGP 邻居 AR1 时按规矩
        "不改下一跳"，于是 AR1 拿到的下一跳还是 10.0.23.3。
        但 AR1 路由表里没有 10.0.23.0/24，这个下一跳解析不出来，
        递归失败，路由不能转发。
  判断：看 Original nexthop。如果它不是本机直连网段里的地址，
        而本机又没有路由能到达它，就是这个问题。
  修法：在 AR2 的 ipv4-family unicast 视图下，给 iBGP 邻居加
        next-hop-local，让它把下一跳改写为自己的地址。
  要点：这句只加在 iBGP 邻居上。加在 eBGP 邻居上不报错但无意义
        （eBGP 本来就改）。

  坑 2：network 用正掩码，不是反掩码
  --------------------------------------------------------------
  OSPF 的 network 是反掩码 0.0.0.255，BGP 的 network 是正掩码
  255.255.255.0。写反了不会提示"掩码错"，只是永远宣告不出去，
  display bgp network 里是空的。
  另外 network 要求路由表里有掩码完全一致的条目，/24 的路由
  不能用 /25 的掩码去宣告。

  坑 3：eBGP 默认 TTL = 1
  --------------------------------------------------------------
  eBGP 邻居之间默认只允许一跳，因为按设计它们必须直连。
  如果两端不是直连（中间隔一台路由器），邻居卡在 Connect/Active，
  必须在邻居上放开跳数限制。本题全部直连，用不到，但这是排错时
  很容易漏的一条。

  坑 4：邻居卡在 Active / Connect 的四个原因
  --------------------------------------------------------------
    1. 对端没配，或 AS 号写错（一端 65001 一端 65002）
    2. 两边 Router ID 撞了
    3. 到自己用的源地址没有路由（多跳场景常见）
    4. eBGP 两端不直连
  排查顺序：先 display bgp peer 看 State，再看两端 AS 号和
  Router ID，最后看底层能不能 ping 通对端接口地址。

  坑 5：只修一侧，变成单向半通
  --------------------------------------------------------------
  AR3 发给 AR4 是同样的问题。只改 AR2 不改 AR3，现象是
  PC1 ping PC2 不通，但 AR1 ping PC2 通 —— 去程有路由、回程没有。
  这种"半通"比彻底不通更难查，因为容易误判成 ACL 或防火墙。
  判据：在两端分别 ping 对方业务地址，看哪个方向丢包。

  坑 6：peer 后面写 Router ID 而不是接口地址
  --------------------------------------------------------------
  邻居是用接口地址建的（10.0.12.2），就必须用这个地址指。
  写成 2.2.2.2（Router ID）邻居起不来，因为 BGP 的 TCP 连接
  是往那个 IP 发起的，不是往 Router ID。

【七、设计点说明】
================================================================

  1. 下一跳是什么
     不是"最终目的地"，而是"这一跳交给谁"。报文每经过一台路由器
     就重新查一次表，一次只决定下一步交给谁。
     下一跳地址必须可达：要么在直连网段里（直接出接口），要么能
     再查到一条路（递归查找）。后者是本题出问题的环节。

  2. eBGP 为什么改下一跳
     边界路由器对外的接入点就是自己那个接口。外部邻居对 AS 内部
     结构一无所知，也不需要知道。所以 eBGP 发出的路由，下一跳
     一律改写成自己："你要去那儿，先到我这来。"

  3. iBGP 为什么不改下一跳
     设计假设：一个 AS 内部跑着 IGP，任何两台路由器之间都互通。
     既然全通，下一跳原样带过去就能用，何必改。
     更深一层的好处是避免流量绕行：如果每台 iBGP 路由器都把下一跳
     改成自己，所有外部流量都会先绕到"离自己最近的那台"再出去，
     AS 内部凭空多一跳。
     本题没跑 IGP，这个假设不成立，所以必须手工补 next-hop-local。

  4. next-hop-local 是补丁，不是标准做法
     真实网络里，AS 内部用 OSPF 或 IS-IS 保证全互通（包括到对方的
     互联接口地址），BGP 只负责搬运外部路由，下一跳自然能解析。
     分工：IGP 管 AS 内可达，BGP 管 AS 间可达。
     验证方法：在 AR1/AR2 上起 OSPF 把 10.0.12.0/24、10.0.23.0/24
     宣告进去，然后删掉 next-hop-local，仍然能通。

  5. AS 号是谁加的、在哪一步加的
     由出口的 eBGP 路由器在发出的那一刻，给每条路由前缀自己的
     AS 号。AR2 发出 192.168.1.0/24 时加上 65001，AR3 收到就是
     65001；AR3 再发给 AR2 的 192.168.2.0/24 带着 65002。
     AR2 本机的 AS-path 显示 Nil，因为本地始发的路由还没经过
     任何一个 AS 边界。

  6. 两层防环，各管一段
     AS 内部：靠 iBGP 水平分割 —— 从 iBGP 邻居学来的路由不再传给
     其他 iBGP 邻居。代价是 AS 内必须全互联或用路由反射器。
     AS 之间：靠 AS_PATH —— 路径里出现自己的 AS 号就丢弃。
     自环的 192.168.2.0/24 绕回 65002 时，AS_PATH 里带着 65002，
     直接被丢。

  7. network 和 import-route 的区别
     network 只把路由表里已存在、掩码精确匹配的路由放进 BGP，
     origin = igp，放哪几条由你一条条点，可审计。
     import-route 把某协议全部路由灌进来，origin = incomplete，
     容易把不该通告的明细、私网段、甚至环路风险一起带出去。
     工程上选 network。

  8. 读输出的陷阱：Relay IP Nexthop 0.0.0.0
     这一列有两层含义，靠 Relay IP Out-interface 是否为空来区分：
       有出接口  -> 下一跳直连，不需要递归，0.0.0.0 表示"无中继地址"
       出接口空  -> 递归失败，下一跳解析不出来，路由作废
     再配合 Paths 行看 best 计数，才不会被同一个 0.0.0.0 骗到。

【八、思考题的答案要点】
================================================================

  1. AR1 收到的 192.168.2.0/24 里只有 65002，那是谁加的？
     由 AR3 在发往 AR2 的那一刻加的。AR2 转发给 iBGP 邻居时
     不加 AS 号，所以 AR1 看到的原样保留。
     证据：AR2 上 192.168.1.0 的 AS-path 是 Nil，但 AR3 收到后
     变成 65001 —— 中间隔的就是 AR2 发出时加的那一次。

  2. iBGP 不加 AS 号，靠什么防环？
     靠 iBGP 水平分割：从 iBGP 邻居学到的路由不再传给其他 iBGP
     邻居。所以三角不会转圈。代价是 AS 内必须全互联，或者用
     路由反射器 / 联邦来打破这个限制。

  3. 如果中间再拉一根线形成环，靠哪个字段拦住？
     AS_PATH。路径里出现自己的 AS 号，整条路由直接丢弃。
     AS 内部靠水平分割，AS 之间靠 AS_PATH，两层各管一段。

  4. network 和 import-route 有什么区别？
     见第七节第 7 条。一句话：network 是点名，import-route 是
     全灌。点名可控可审计，全灌容易出事。
