================================================================
  第 14 题 · BGP 路由过滤与 Community（完整配置）
  设备：4 台 AR2220 + 2 台 PC（链式拓扑，三 AS）
  日期：2026-11-28
  版本：VRP V200R003C00（eNSP）
================================================================

  本题是整条 BGP 主线上的"控制面收口"：
  前面 11~13 题解决的是"怎么通、选哪条、邻居太多怎么减"，
  本题解决的是"哪些路由允许被谁看见、被谁转发"。

  六个任务覆盖三种过滤手段，层层递进：

    任务 3  filter-policy ip-prefix export   全局筛，只能筛不能改
    任务 4  apply community no-export        路由自带标签，跟路由走
    任务 5  as-path-filter import            按 AS_PATH 正则筛入方向
    任务 6  peer x route-policy export       点对点，可筛可改

  本文配置与数据全部来自设备实时回显（display 原始输出），
  包含两次失败过程，不是按方案推演写的。

【一、拓扑速览】
================================================================

        PC1 192.168.1.10
              |
        [AR1] 1.1.1.1   AS 65001
              |  10.0.12.0/24   iBGP
        [AR2] 2.2.2.2   AS 65001

  一条直线，四台路由器，三个 AS。

  这一点决定了本题的验证方式（见任务 6 的坑）。

  192.168.1.0/24   AR1 的接入口，从 AR2 那边看是"上游"
  192.168.2.0/24   AR4 的接入口（PC2 所在）
  192.168.3.0/24   AR4 的 LoopBack1，允许全网可见
  192.168.4.0/24   AR4 的 LoopBack2，内部网段，不应该出 AS 65003
  192.168.9.0/24   AR3 的 LoopBack0，任务 5 才宣告

  连接表（5 根线，全程 Copper）：

  +------+-------------------+-------------------+---------------+
  | 序号 | A 端              | B 端              | 承载网段      |
  +------+-------------------+-------------------+---------------+
  |  1   | PC1 Ethernet0/0/1 | AR1 GE0/0/0       | 192.168.1.0   |
  |  2   | AR1 GE0/0/1       | AR2 GE0/0/0       | 10.0.12.0     |
  |  3   | AR2 GE0/0/1       | AR3 GE0/0/0       | 10.0.23.0     |

  |  5   | AR4 GE0/0/1       | PC2 Ethernet0/0/1 | 192.168.2.0   |

----------------------------------------------------------------
  4.1  AR1 —— AS 65001 内部
----------------------------------------------------------------

  sysname AR1
  #
  interface GigabitEthernet0/0/0
   ip address 192.168.1.254 255.255.255.0
  #
  interface GigabitEthernet0/0/1
   ip address 10.0.12.1 255.255.255.0
  #
  bgp 65001
   router-id 1.1.1.1
   peer 10.0.12.2 as-number 65001
   #
   ipv4-family unicast
    undo synchronization
    network 192.168.1.0
    peer 10.0.12.2 enable

  说明：AR1 是纯 iBGP 端，不做任何过滤，全程只当"观测点"。


----------------------------------------------------------------
  4.2  AR2 —— AS 65001 边界 + 任务 5 的过滤器
----------------------------------------------------------------

  sysname AR2
  #
  interface GigabitEthernet0/0/0
   ip address 10.0.12.2 255.255.255.0
  #
  interface GigabitEthernet0/0/1
   ip address 10.0.23.2 255.255.255.0
  #
  bgp 65001
   router-id 2.2.2.2
   peer 10.0.12.1 as-number 65001
   peer 10.0.23.3 as-number 65002
   #
   ipv4-family unicast
    undo synchronization
    peer 10.0.12.1 enable
    peer 10.0.12.1 next-hop-local
    peer 10.0.23.3 enable
    peer 10.0.23.3 as-path-filter 1 import
  #
  ip as-path-filter 1 permit _65003$

  两处关键：
    next-hop-local   把发给 AR1 的路由下一跳改成本机 10.0.12.2
    as-path-filter   只收 AS_PATH 以 65003 结尾的路由（任务 5）


----------------------------------------------------------------
  4.3  AR3 —— AS 65002 中转 + 任务 5/6 的源头

  sysname AR3

----------------------------------------------------------------
  4.4  AR4 —— AS 65003 末端 + 任务 3/4 的源头
----------------------------------------------------------------

  sysname AR4
  #
  interface GigabitEthernet0/0/0
   ip address 10.0.34.4 255.255.255.0
  #
  interface GigabitEthernet0/0/1
   ip address 192.168.2.254 255.255.255.0
  #
  interface LoopBack1
   ip address 192.168.3.1 255.255.255.0
  #
  interface LoopBack2
   ip address 192.168.4.1 255.255.255.0
  #
  bgp 65003
   router-id 4.4.4.4
   peer 10.0.34.3 as-number 65002
   #

    network 192.168.3.0

【五、六个任务逐个落地】
================================================================

----------------------------------------------------------------
  任务 1：基础 IP + 建全 BGP 邻居
----------------------------------------------------------------

  目标：四台起邻居，链式两跳，全部 Established。

  做法：四台按第二节配 IP，然后建 BGP。
        AR1-AR2 同属 65001，是 iBGP；
        AR2-AR3、AR3-AR4 是 eBGP。

  结果：

    设备    邻居数    状态
    AR1       1       Established
    AR2       2       Established
    AR3       2       Established
    AR4       1       Established

  注意：AR3 和 AR4 是单路由器 AS，不需要 iBGP；
        AR2 同时有 iBGP 和 eBGP 邻居，是本题唯一的三方交汇点。


----------------------------------------------------------------
  任务 2：全网互通，AR1 拿到 2.0/3.0/4.0
----------------------------------------------------------------

  目标：AR1 的 BGP 表出现三条 192.168.x，PC1 能 ping 通 PC2。

  只建邻居不做额外处理会出现的问题：

    AR1 收到的路由下一跳是 AR4 的 10.0.34.4
    （eBGP 邻居 AR2 转发时不改下一跳）
    AR1 没有到 10.0.34.0/24 的路由（全网无 IGP）
    -> 路由在 BGP 表里是 valid，但进不了 FIB，ping 不通

  解决（在 AR2 上）：

    bgp 65001
     ipv4-family unicast
      peer 10.0.12.1 next-hop-local

  规则要记牢：next-hop-local 挂在【iBGP 邻居】上，
  不挂在 eBGP 邻居上（eBGP 邻居的下一跳本来就是本机）。

  加完实测：

    AR1 三条，AS_PATH 均为 65002 65003
    PC1 ping PC2 通，ttl=125

  另外第 14 题一开始 PC1 就是 ping 不通 PC2，路由器侧双向都通
  （AR1->PC2 ttl=125，PC2->AR1 也通），最后是 PC1 的网关
  没点【应用】。所以 PC 不通先查三项：
    1. IP 和掩码
    2. 网关
    3. 点了【应用】没有


----------------------------------------------------------------
  任务 3：AR4 用 filter-policy 只通告 2.0/3.0
----------------------------------------------------------------

  目标：4.0 不许出 AS 65003，但 AR4 自己仍要能访问 4.0。

  做法（AR4）：

    ip ip-prefix AB index 10 permit 192.168.2.0 24
    ip ip-prefix AB index 20 permit 192.168.3.0 24
    bgp 65003
     ipv4-family unicast
      filter-policy ip-prefix AB export

  实测结果：

    AR4 自己     4 条（本地 network，不受出口过滤影响）
    AR3          3 条（缺 4.0）
    AR2 / AR1    各 3 条（缺 4.0）

  最重要的认知：filter-policy export 只影响"发出去"，
  不影响本机路由表。AR4 上 4.0 永远在。

  该配置后来被任务 4 撤销（见下），最终配置里没有它。


----------------------------------------------------------------
  任务 4：改用 Community no-export，让 4.0 自带标签
----------------------------------------------------------------

  目标：同样是 4.0 不外传，但改用 BGP 社区属性实现。

  先撤销任务 3：

    bgp 65003
     ipv4-family unicast
      undo filter-policy ip-prefix AB export

  再配（AR4）：

    ip ip-prefix ONLY4 index 10 permit 192.168.4.0 24
    route-policy NOEXP permit node 10
     if-match ip-prefix ONLY4
     apply community no-export
    #
    route-policy NOEXP permit node 20

    bgp 65003
     ipv4-family unicast
      peer 10.0.34.3 route-policy NOEXP export
      peer 10.0.34.3 advertise-community

  这里的两次失败（本题最值钱的部分）：

  失败一：route-policy 少了 node 20
    有 if-match 的节点，未匹配的路由默认被拒。
    只写 node 10 的后果是 2.0、3.0 也一起被挡掉，
    因为 4.0 之外的路由都"没匹配上"。
    实测现象：AR3 一条都不剩。

  失败二：peer 引用了前缀列表的名字
    前缀列表叫 ONLY4，策略叫 NOEXP，peer 那行却写成
    peer 10.0.34.3 route-policy ONLY4 export
    华为不报错，静默失效，和没事一样。

    唯一铁证：
      display route-policy
      -> matched counts: 0

  正确后的实测证据（AR3 上）：

    display bgp routing-table 192.168.4.0

    BGP routing table entry information of 192.168.4.0/24
    From: 10.0.34.4 (4.4.4.4)
    Route Duration: ...
    Community: no-export
    Not advertised to any peer yet      <- 核心
    AS-path 65003, origin igp

  no-export 的准确含义：
    AR3 收到了、认可了、也写进表了，但 AR3 在往外发的时候
    看到这个标签，就不再发给任何 eBGP 邻居。
    "不传出本 AS"，不是"不给对端"。

  这就是任务 3 和任务 4 的本质区别：
    filter-policy  在【发送方】门口拦，路由根本不带标签
    no-export      在【路由自己身上】贴标签，每台设备都认
    所以任务 4 的做法，中途换设备、加 AS 都还成立。


----------------------------------------------------------------
  任务 5：AR3 宣告 9.0，AR2 只收 65003 结尾的路由
----------------------------------------------------------------

  目标：AR3 的 LoopBack0 宣告出去，但到不了 AR1。

  第一步（AR3）：

    bgp 65002
     ipv4-family unicast
      network 192.168.9.0 255.255.255.0

  第二步（AR2）：

    ip as-path-filter 1 permit _65003$
    bgp 65001
     ipv4-family unicast
      peer 10.0.23.3 as-path-filter 1 import

  为什么这样写：

    AR2 从 AR3 收 9.0，AS_PATH 是 "65002"
    AR2 从 AR3 收 3.0，AS_PATH 是 "65002 65003"
    正则 _65003$  = 以 AS 边界开头、到 65003 结尾
    9.0 结尾是 65002，被拒；3.0 结尾是 65003，放行。

  实测（任务 5 完成时）：

    设备   条数  有没有 192.168.9.0
    AR3     5    有（本地 network，Path 为空）
    AR2     3    没有
    AR1     3    没有
    AR4     5    有（65002i，AR3 对 AR4 没做过滤）

  AR4 也拿到 9.0 属于正常：过滤只加在 AR2 -> AR3 这条入方向，
  不涉及 AR3 -> AR4。

  两个语法坑：
    1. as-path-filter 末尾也有隐含 deny，一条 permit 就够了
    2. $ 是路径结尾，^ 是路径开头，_ 是 AS 边界（空格、逗号也算）
       想匹配"只有一段 65003"必须写 ^65003$，
       写 _65003$ 会连 "65002 65003" 一起放进来


----------------------------------------------------------------
  任务 6：只不许把 192.168.1.0 发给 AR4
----------------------------------------------------------------

  目标：AR4 看不见 192.168.1.0/24，但 AR3 自己仍能访问。

  这一版是【修正版】，原始设计的对象选错了，坑记在下面。

  做法（AR3）：

    ip ip-prefix ONLY1 index 10 permit 192.168.1.0 24
    route-policy NO1 deny node 10
     if-match ip-prefix ONLY1
    #
    route-policy NO1 permit node 20

    bgp 65002
     ipv4-family unicast
      peer 10.0.34.4 route-policy NO1 export

  和任务 4 的写法差异：
    任务 4 是 permit 节点 + apply 动作（打标签）
    任务 6 是 deny 节点（直接拒），所以 node 10 必须是 deny

  实测（最终状态）：

    AR3: display route-policy
      Route-policy : NO1
        deny : 10 (matched counts: 1)
          if-match ip-prefix ONLY1
        permit : 20 (matched counts: 1)

    AR4: display bgp routing-table
      Total Number of Routes: 4
      192.168.2.0    0.0.0.0        i        <- 本地
      192.168.3.0    0.0.0.0        i        <- 本地
      192.168.4.0    0.0.0.0        i        <- 本地
      192.168.9.0    10.0.34.3   65002i      <- 唯一外来路由

    AR4: ping 192.168.1.10
      Request time out

  deny 命中 1 次、permit 命中 1 次，正好对上 AR3 发给 AR4 的
  两条路由（1.0 和 9.0）。数字对得上才叫验证通过。

  ------------------------------------------------------------
  【原始设计错在哪】
  ------------------------------------------------------------

  最初的题目是"让 192.168.3.0/24 只不许发给 AR4"，
  配完在 AR4 上看，3.0 依然在，看起来像没生效：

    Route-policy : NO3
      deny : 10 (matched counts: 0)     <- 一次都没命中
      permit : 20 (matched counts: 2)   <- 只有 1.0 和 9.0 出去了

  原因有两层：

  1. 192.168.3.0 是 AR4 自己的 LoopBack1，由 AR4 自己 network 出来。
     AR3 从 AR4 学到它，BGP 靠 AS_PATH 防环，不会把 AR4 始发的
     路由再发回 AR4。所以这条路由压根没进过 export 策略。

  2. AR4 表里那条 3.0 的下一跳是 0.0.0.0、Origin 是 i，
     说明它是【本地路由】，不是从 AR3 学来的。
     任何 export 策略都管不到本机 network 出来的路由。

  教训：选过滤对象时，必须选"经过本机、且确实会发给目标邻居"的路由。
       本地始发的路由，本机永远有一条，从对端永远测不出来。

  另一个隐藏结论（链式拓扑的通病）：
       一条路由在一台设备上通常只有一个"有效下游"，
       所以 filter-policy（全局）和 peer route-policy（点对点）
       在业务层面看不出差别。要看出差别，得看 advertised 表：

         display bgp routing-table peer 10.0.23.2 advertised-routes

       全局过滤会连发往 AR2 的那份一起消失，
       点对点过滤则只有发往 AR4 的那份消失。

【七、三种过滤手段对照表】
================================================================

  +---------------------+----------+--------+--------+----------+
  | 手段                | 作用范围 | 能筛   | 能改   | 典型用途 |
  |                     |          |        | 属性   |          |
  +---------------------+----------+--------+--------+----------+
  | filter-policy       | 全局     | 是     | 否     | 整台设备 |
  |   ip-prefix export  | 所有邻居 |        |        | 统一出口 |
  +---------------------+----------+--------+--------+----------+
  | peer x route-policy | 单个邻居 | 是     | 是     | 按邻居 |
  |   export / import   |          |        |        | 差异化 |
  +---------------------+----------+--------+--------+----------+
  | filter-policy       | 全局     | 是     | 否     | 少用，   |
  |   ... import        |          |        |        | 易误伤   |
  +---------------------+----------+--------+--------+----------+
  | peer x as-path-     | 单个邻居 | 是     | 否     | 按 AS   |
  |   filter import     |          |        |        | 拓扑筛   |
  +---------------------+----------+--------+--------+----------+
  | community           | 跟路由走 | 是     | 是     | 跨设备   |
  |                     | 跨 AS    |        |        | 统一策略 |
  +---------------------+----------+--------+--------+----------+

  三句话总结：

    要"只对某个邻居"  -> peer x route-policy export
    要"跨设备都认"    -> community + 双方 advertise-community
    要"按 AS_PATH 筛" -> as-path-filter import

  filter-policy export 的定位：省事，但一刀切。
  本题任务 6 如果把 filter-policy 挂上去，AR3 发给 AR2 的
  1.0 也会一起被挡（虽然 AR2 有直连看不出来），
  这就是"全局"两个字的代价。

【八、踩坑清单】
================================================================

  1. 前缀列表名和策略名混用（本题两次，第 12 题一次）
     前缀列表 ONLY4、策略 NOEXP，peer 行写成 route-policy ONLY4
     华为不报错，静默失效。
     唯一证据：display route-policy 的 matched counts 为 0。

  2. ip-prefix 的掩码写长度数字，不写点分
     对：ip ip-prefix ONLY4 index 10 permit 192.168.4.0 24
     错：ip ip-prefix ONLY4 index 10 permit 192.168.4.0 255.255.255.0

  3. ip-prefix 末尾隐含 deny
     想"只挡一个、放行其余"，必须再写一条 permit 0.0.0.0 0
     less-equal 32，或者让 route-policy 的空节点兜底。

  4. route-policy 有 if-match 的节点，未匹配路由默认被拒
     必须加空的 permit node 20。
     只写 if-match 节点 = 把其他所有路由一起杀掉。

  5. community 默认不传递
     发送方不配 advertise-community，社区属性根本不进报文。
     任务 3 的 filter-policy 和任务 4 的 no-export 差别就在这：
     前者是"发送方不发"，后者是"路由自带记号，谁看都懂"。

  6. no-export 不等于"对端收不到"
     no-export：对端能收到、能装表，但不再往外发（不传出本 AS）
     no-advertise：谁也不给，连对端都收不到
     internet：可以给任何人（默认行为）

  7. 过滤对象必须自己走一遍"路由从哪来、要发到哪"
     3.0 是 AR4 自己的 loopback，AS_PATH 防环让它不会回到 AR4，
     所以"不许发给 AR4"这个题根本无从生效。
     选对象前先看 display bgp routing-table 里的 NextHop：
     0.0.0.0 + Origin i = 本地始发，任何 export 策略都测不出来。

  8. screen-length 0 temporary 在 eNSP AR 上报错
     Error: The type of the included user interface must be VTY.
     这版不支持临时设置分页。
     替代：抓配置时分段查（configuration bgp / ip interface brief），
     或用自动翻页（发空格推进 ---- More ----）。
     分页字符会污染后续输入，造成一片假 Error: Unrecognized command。

  9. eNSP 虚拟机僵尸导致配置全丢
     VBoxManage list runningvms 为空，但 VBoxHeadless 进程残留 12 个
     （正常每个 400~500MB，僵尸只有 6~48MB）。
     现象：四台 console 全返回 ##、进不了视图、按启动无效。
     处理：管理员权限 taskkill /F /IM VBoxHeadless.exe 后重启 eNSP。
     教训：配完立刻 save，别等全部做完再存。

  10. 路由表里的 LocPrf 100 是 iBGP 默认值
      AR1 上三条路由都带 LocPrf 100，不代表设过 Local_Pref，
      那是 iBGP 学习到的路由的默认显示。别误判。

【九、思考题要点】
================================================================

  1. filter-policy ip-prefix export 到底是让对端"没收到"，
     还是"收到又丢了"？

     没收到。过滤器在本地 BGP 的出口方向执行，
     被过滤的路由根本不会进入 Update 报文。
     对端 display bgp routing-table 里连影子都没有，
     也没法用 received-routes 看到。

     对比 no-export：对端收到了、装表了，
     只是它自己不转发。两者在"对端有没有这条路由"
     这个问题上，答案完全不同。

  2. 三个预定义社区怎么分层？

     no-advertise  最狠：谁也不给，连本 AS 内 iBGP 邻居都不给
                   （严格说：不向任何 BGP 邻居通告）
     no-export     次之：不给本 AS 以外的 AS，AS 内部照常传
     internet      最松：可以给任何人，等于没打标签

     本题用的是中间的 no-export，所以 AR3 收得到（AR3 是
     相邻 AS，算"对端"），但 AR3 不会再发给别人。

  3. 如果 AR2 有 20 个邻居，要"只挡 4.0 发给其中 5 个"，
     用哪种手段？

     只能用 peer x route-policy export，逐个邻居挂。
     15 个邻居要放行、5 个要挡，就得写 5 条 peer 语句。

     filter-policy export 完全做不到（一挡全挡）。

     如果这 5 个邻居分属不同 AS，还有更省事的办法：
     对端配 peer x as-path-filter import 按 AS 号筛，
     或者发送方按 AS 打不同的 community，对端按 community 筛。
     这就是大规模网络里 community 的真正价值 ——
     把"策略"从"逐邻居配置"变成"按标签集中控制"。

  4. ^65002 65003$ 和 _65003$ 有什么区别？

     ^65002 65003$
       要求 AS_PATH 恰好两段、顺序固定、头尾严丝合缝。
       "65002 65003" 匹配；"65001 65002 65003" 不匹配；
       "65003" 也不匹配。

     _65003$
       只要求结尾是 65003，前面有多少段都行。
       "65003"、"65002 65003"、"65001 65002 65003" 全匹配。

     本题在 AR2 上用 _65003$，是因为要放过所有从 65003 起源
     的路由，不管中间经过几个 AS（现在只有 65002 一跳，
     将来加 AS 也不用改配置）。
     如果要精确锁定"65003 直接连 65002"这种拓扑，
     才用 ^65002 65003$。
