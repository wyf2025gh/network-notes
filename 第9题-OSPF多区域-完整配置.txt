【四、设备配置】
================================================================

----------------------------------------------------------------
  AR2（左边界 ABR：Area 1 <-> Area 0，汇总在这里做）
----------------------------------------------------------------

system-view
sysname AR2

interface GigabitEthernet0/0/0
 ip address 192.168.1.254 24
quit

interface GigabitEthernet0/0/1
 ip address 10.0.12.1 30
quit

interface LoopBack0
 ip address 192.168.10.1 24
quit

ospf 1 router-id 2.2.2.2
 area 1
  network 192.168.1.0 0.0.0.255
  network 192.168.10.0 0.0.0.255
  abr-summary 192.168.0.0 255.255.0.0
  quit
 area 0
  network 10.0.12.0 0.0.0.3
  quit
quit

save

【五、验证命令】
================================================================

  ① 邻居状态
  --------------------------------------------------------------
  在 AR1：display ospf peer brief
    期望 2 条，State 全为 Full（2.2.2.2 走 G0/0/0，3.3.3.3 走 G0/0/1）
  在 AR2：display ospf peer brief
    期望 1 条，对端 1.1.1.1，Full
  在 AR3：display ospf peer brief
    期望 1 条，对端 1.1.1.1，Full
  合计 4 条邻居关系。出现 Init / 空白，先查两端的接口掩码与区域号。

  ② ABR 身份
  --------------------------------------------------------------
  在 AR2 / AR3：display ospf brief
    期望 Border Router: AREA，Area Count: 2
  在 AR1：display ospf brief
    期望不是 AREA（它只在 Area 0 内部，不算 ABR）

  ③ 汇总是否生效（本题核心）
  --------------------------------------------------------------
  在 AR2：display ip routing-table | include 192.168
    期望 2 条直连：192.168.1.0/24（GE0/0/0）
                    192.168.10.0/24（LoopBack0）

  在 AR3：display ip routing-table | include 192.168
    期望只有 1 条：192.168.0.0/16  OSPF  10  → 10.0.13.1
    两条 /24 明细必须消失

  判据：AR2 有明细、AR3 没有，才叫汇总生效。
  如果 AR3 上两条 /24 还在，只可能是三种原因：
    - abr-summary 敲进了错误区域的视图
    - 掩码写成了反掩码 0.0.255.255
    - 网段根本不在汇总范围内

  ④ LSA 类型
  --------------------------------------------------------------
  在 AR2：display ospf lsdb
    期望看到 Router / Network / Sum-Net 三类
  在 AR3：display ospf lsdb summary
    期望只有 192.168.0.0/16 一条 Type-3，没有 /24

  ⑤ 端到端
  --------------------------------------------------------------
  PC1：ping 192.168.2.10
    期望 5/5，ttl = 125
    128 - 3 = 125，经过 AR2、AR1、AR3 共三次三层转发
    首包超时属于 ARP 或 OSPF 收敛，正常现象

【六、本题实测踩坑记录】
================================================================

  坑 1：AR1 GE0/0/0 掩码打成 /24，OSPF 邻居起不来
  --------------------------------------------------------------
  现象：PC 之间 ping 得通，AR1 和 AR2 的接口都 up，地址也都在，
        display ospf peer brief 却是空的（或卡在 Init）。
  原因：一端 /30、一端 /24。OSPF 在 Broadcast 网络上会校验 Hello
        报文里携带的接口掩码，两端不一致就直接丢弃 Hello。
        ARP 和 ICMP 都不做这个检查，所以 ping 完全正常。
  修法：把 AR1 GE0/0/0 改成 10.0.12.2 30。
  要点：两端都错成 /24 反而能建邻居（掩码一致就通过校验），
        只有"一端 /30 一端 /24"这种不对称才致命。
  排查：display ip interface brief 把两端并排看掩码列。

  坑 2：abr-summary 的掩码是正掩码
  --------------------------------------------------------------
  同一个 OSPF 进程里两种掩码并存：
    network      用反掩码   192.168.1.0 0.0.0.255
    abr-summary  用正掩码   192.168.0.0 255.255.0.0
  写成 0.0.255.255 不会报错，但汇总结果错误或根本没效果。

  坑 3：abr-summary 必须在"被汇总区域"的 area 视图下
  --------------------------------------------------------------
  要汇总 Area 1 的网段，就进 area 1 敲。
  在 area 0 里敲，语义变成"汇总 Area 0 并通告出去"，完全跑偏。
  判断法：要隐藏哪个区域的细节，就进哪个区域。

  坑 4：Area 0 的网段不能被汇总
  --------------------------------------------------------------
  Area 0 是公共骨干，不属于任何需要被概括的普通区域。

【七、设计点说明】
================================================================

  1. 为什么 AR1 的 LoopBack0 也要宣告
     Area 0 里如果只有两条 /30 互联网段，骨干区域一旦某条链路
     故障就缺少备份路径的验证依据。宣告环回也可让 Area 0 的
     Router LSA 更完整。写 network 1.1.1.1 0.0.0.0，反掩码全 0
     表示精确匹配这一台主机。

  2. 为什么 AR2 要单独造 192.168.10.0/24
     汇总要"合并"至少需要两个对象。Area 1 只有 192.168.1.0/24
     一条时，abr-summary 敲下去也"成功"，但路由表看不出变化，
     无法判断是否真的生效。加一条环回网段后：
       汇总前 AR3 看到 2 条 /24  ->  汇总后只剩 1 条 /16
     这才是可判读的证据。
     用环回而不是加 PC 的三个理由：省资源、永远 up、
     符合工程上"用环回模拟区域内其他网段"的惯例。

  3. 为什么汇总不改变 AR2 自己的路由表
     Type-3 LSA 是 ABR 把区域内路由"翻译"后通告给其他区域的。
     汇总发生在"我告诉别人的内容"里，不发生在"我自己的路由表"里。
     所以 AR2 本机仍有两条明细（那是直连），AR3 只看到合并后的 /16。
     一句话：汇总不改变自己怎么走，只改变别人怎么看你。

  4. 为什么 AR3 也能当 ABR
     ABR 的判定是"至少有一个接口在 Area 0，且至少有一个接口在
     其他区域"。AR3 的 GE0/0/0 在 Area 0、GE0/0/1 在 Area 2，
     满足条件。AR1 两个口都在 Area 0，所以不是 ABR。

【八、三个思考题的答案要点】
================================================================

  1. 若把 AR2-AR1 链路划进 Area 1，AR3 的 Area 2 还学得到 192.168.1.0/24 吗？
     学不到。区域间路由必须经过 Area 0 中转，非骨干区域不能直接
     交换 Type-3。AR2 和 AR3 之间失去了共同骨干路径，OSPF 会因
     "非骨干区域未直连 Area 0"而无法完成区域间路由计算。

  2. IS-IS 的 NET 地址由哪几段组成？和 Router ID 是一回事吗？
     NET = AFI(49) + Area ID + System ID(6 字节) + SEL(00)，
     例：49.0001.0000.0000.0001.00
     System ID 通常由 Router ID 转换而来，作用类似（唯一标识一台
     路由器），但 NET 额外携带了区域信息，这是 OSPF 的 Router ID
     不具备的。IS-IS 的区域边界体现在 NET 的 Area ID 上，
     OSPF 体现在接口所属的 area 上。

  3. BGP 的 AS 号起什么作用？为什么 eNSP 里常用 65001？
     AS 号标识一个自治系统，BGP 用它做路径矢量防环（AS_PATH 中
     出现自己的 AS 号就丢弃）。1-64511 是公网注册 AS，64512-65534
     是私有 AS，65001 落在私有段内，实验室随便用不会和公网冲突。
