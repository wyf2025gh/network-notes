【一、拓扑速览】

              AS 65001                        AS 65002

                    +---- AR2 ----+
                    |             |
   PC1 ---- AR1 ----+             +---- AR4 ---- PC2
                    |             |
                    +---- AR3 ----+
                    （AR2 与 AR3 之间还有一条线）

  不是链，是"日"字形：AS 65001 内部三台全互联，两个出口各连 AR4。

  设备角色：

  AR1  AS 65001 内部，纯 iBGP 汇聚点，192.168.1.0/24 从它始发
  AR2  AS 65001 边界，对内 iBGP、对外 eBGP，出口 1
  AR3  AS 65001 边界，对内 iBGP、对外 eBGP，出口 2
  AR4  AS 65002 唯一路由器，两条 eBGP 分别接 AR2 / AR3

  AR4 是单路由器 AS，所以 AS 65002 内部没有 iBGP，
  两条到 AR2 / AR3 的邻居都是 eBGP。

  连接表（6 根线，全程 Copper）：

  +------+-------------------+-------------------+---------------+
  | 序号 | A 端              | B 端              | 承载网段      |
  +------+-------------------+-------------------+---------------+
  |  1   | PC1 Ethernet0/0/1 | AR1 GE0/0/0       | 192.168.1.0   |
  |  2   | AR1 GE0/0/1       | AR2 GE0/0/0       | 10.0.12.0     |
  |  3   | AR1 GE0/0/2       | AR3 GE0/0/0       | 10.0.13.0     |
  |  4   | AR2 GE0/0/2       | AR3 GE0/0/2       | 10.0.23.0     |
  |  5   | AR2 GE0/0/1       | AR4 GE0/0/0       | 10.0.24.0     |
  |  6   | AR3 GE0/0/1       | AR4 GE0/0/1       | 10.0.34.0     |
  |  7   | AR4 GE0/0/2       | PC2 Ethernet0/0/1 | 192.168.2.0   |
  +------+-------------------+-------------------+---------------+

  （表中 7 行，其中 PC 两条不计入路由器互联，路由器之间 5 根）

  第 4 根线（10.0.23.0/24）是本题的关键：
  它上面不跑 BGP（AR2 与 AR3 之间的 iBGP 用环回建），
  但它让"三条 iBGP 全互联"在物理上成为可能。

【五、任务 3：用 Local_Pref 把 AR1 的出向改到 AR3】
================================================================

  做法：在 AR3 上，对"从 AR4 学来的路由"设 Local_Pref 200。
  不能直接挂在邻居上，必须借 route-policy。

  AR3：

system-view
route-policy LP permit node 10
 apply local-preference 200
quit
bgp 65001
 ipv4-family unicast
  peer 10.0.34.4 route-policy LP import
 quit
quit

  三个要点：
    ① 方向是 import（收进来时改），不是 export
    ② 必须先进 ipv4-family unicast 视图
    ③ Local_Pref 默认 100，越大越优先

  撤销（做 MED 实验前必须先撤，否则 Local_Pref 会压住 MED）：

bgp 65001
 ipv4-family unicast
  undo peer 10.0.34.4 route-policy LP import
 quit
quit

================================================================
【六、任务 5：用 MED 控制进入 AS 65002 的方向】
================================================================

  做法：在 AR4 上，按邻居分别设 MED。
  数值越小越优先，所以给 AR3 设 100、给 AR2 设 200。

  AR4：

system-view
route-policy ABC permit node 10
 apply cost 200
quit
route-policy CD permit node 10
 apply cost 100
quit
bgp 65002
 ipv4-family unicast
  peer 10.0.24.2 route-policy ABC export
  peer 10.0.34.3 route-policy CD export
 quit
quit

  四个要点：
    ① BGP 里 apply cost 就是设 MED，名字叫 cost 但作用不是 IGP 开销
    ② 方向是 export（发出去时加），和 Local_Pref 正好相反
    ③ MED 越小越优先，和 Local_Pref 正好相反
    ④ 策略名字必须和设备上定义的一致，写错了不报错、静默失效

  补充说明（任务描述里的"回程"）：
    MED 能控制的只是"AS 65001 去 PC2 走哪个口"。
    AR4 自己回程选 192.168.1.0/24 走哪条，MED 管不到 ——
    那是 AR4 自己的本地决策，要用 Local_Pref。
    本题 AR4 回程走 AR2（Router ID 2.2.2.2 < 3.3.3.3 决胜）。
    想让 AR4 回程也走 AR3，得在 AR4 上对 peer 10.0.34.3
    加 import 策略设 local-preference 200，属于另一个实验。

【八、设计点说明】
================================================================

  1. BGP 选路顺序（本题的核心框架）
  --------------------------------------------------------------
  两台路由器对同一条前缀各有一条路径时，按下面的顺序比，
  谁的层级分出来就停止，后面全部不看：

    ① 最高的 Local_Pref
    ② 最短的 AS_PATH
    ③ 最小的 Origin（igp < egp < incomplete）
    ④ 最小的 MED
    ⑤ eBGP 优先于 iBGP
    ⑥ 到下一跳 IGP 开销最小的
    ⑦ 邻居 Router ID 最小的（有的版本还有集群长度等）

  本题四条路径的实际情况：①②③④⑤ 全部打平，
  一路比到 ⑦ 才分出胜负 —— 这就是"为什么最后靠 Router ID"。

  2. Local_Pref：本 AS 内部的意见
  --------------------------------------------------------------
  传播：iBGP 传，eBGP 一出 AS 就丢弃
  数值：默认 100，越大越优先
  作用：本 AS 的流量从哪个出口出去
  特点：自己说了算，别人看不到也管不着

  3. MED：对外部的建议
  --------------------------------------------------------------
  传播：eBGP 传给邻居 AS，但**不再往下传**（可选非传递属性）
  数值：默认 0，越小越优先
  作用：建议邻居"进我这边走这个口"
  特点：只是建议，对方可以不听（比如对方 Local_Pref 更高）

  这就是为什么 Local_Pref 的优先级高于 MED：
  自己的意见优先于别人的建议。

  4. 为什么 AS_PATH 区分不出同一个 AS 的两个出口
  --------------------------------------------------------------
  AS_PATH 记录的是"AS 号"，不是"路由器"。
  AR2 和 AR3 都属于 65001，发出去时加的都是 65001，
  所以 AR4 看到的两条路径 AS-path 完全一样，长度都是 1。

  推论：AS_PATH 无法表达"同一个 AS 有多个入口"，
  这正是 MED 存在的理由。

  5. Local_Pref 的连锁反应（本题最大的意外）
  --------------------------------------------------------------
  AR3 上把 Local_Pref 设成 200 之后，这个值会随路由一起
  通告给 AR2。AR2 拿它和直连 eBGP 的 100 比较，AR3 赢，
  于是 AR2 自己的 best 也变了。

  但 BGP 只通告"自己的 best"，而 best 现在是从 iBGP 学来的
  —— iBGP 水平分割规定：从 iBGP 邻居学到的路由，
  不再传给其他 iBGP 邻居。于是 AR2 不再向 AR1 通告，
  AR1 表里的路径从 2 条变成 1 条。

  结论：改一个 Local_Pref，影响范围不止一台路由器，
  整个 AS 的选路和通告行为都会跟着变。

  6. next-hop-local 与 connect-interface 的乘积效应
  --------------------------------------------------------------
  iBGP 默认不改下一跳。AR2 从 AR4 学来的下一跳是
  10.0.24.4，转给 AR1 时原样带过去，AR1 不认识这个地址，
  递归失败，路由不能转发（0 best）。

  加 next-hop-local 后，下一跳被改成"建立邻居时用的源地址"。
  因为邻居是用 connect-interface LoopBack0 建的，
  所以下一跳变成环回地址 2.2.2.2，而不是接口地址 10.0.12.2。
  接着 AR1 用 OSPF 把 2.2.2.2 递归解析到 10.0.12.2，
  路由生效。

  输出里的对应证据：
    Original nexthop: 2.2.2.2
    Relay IP Nexthop: 10.0.12.2      <-- 递归结果
    Relay IP Out-Interface: G0/0/1

  7. IGP 与 BGP 的分工
  --------------------------------------------------------------
  OSPF 负责 AS 内部可达（三台路由器互相能找到环回）
  BGP  负责 AS 之间可达（192.168.1.0/24 与 192.168.2.0/24）

  两者不是二选一：
    没有 OSPF，iBGP 邻居起不来（环回不可达）
    没有 BGP，跨 AS 的业务网段传不过去

  8. 为什么 10.0.24.0/24 和 10.0.34.0/24 不进 OSPF
  --------------------------------------------------------------
  它们是 AS 间互联段，另一端不完全由自己控制。
  放进 LSDB 等于让外部因素参与内部 SPF 计算，
  AR4 那头一抖，AR1、AR2 都要跟着重算。

  IGP 应该只描述"我自己的拓扑"。

  9. 真正不能做的：把 192.168.2.0/24 灌进 OSPF
  --------------------------------------------------------------
  一旦进入 OSPF，AR1 会同时从 OSPF（优先级 10）和
  BGP（优先级 255）学到它。OSPF 优先级高，BGP 直接失效，
  Local_Pref、best、路径对比全部看不到。

  这是 BGP 实验最常见的"配了但没效果"的原因。

【九、本题实测踩坑记录】
================================================================

  坑 1：peer 写环回地址，但环回之间没有路由 → Idle
  --------------------------------------------------------------
  现象：三台 AS 65001 的 peer 全写成 2.2.2.2 / 3.3.3.3，
        LoopBack0 也确实建好了、地址全对，
        但 display bgp peer 全是 Idle，挂了十几分钟。
  真相：环回是 /32 主机地址，不属于任何直连网段。
        全网没有任何路由能到 2.2.2.2，
        AR1 ping 2.2.2.2 100% 丢包，
        display ip routing-table 2.2.2.2 是空的。
        BGP 要打 TCP 179，路由都没有，连 SYN 都发不出去，
        所以停在 Idle 而不是 Active。
  判断：peer 后面那个地址，必须能 ping 通。
  修法：AS 65001 内跑 OSPF，把三台的环回和互联段宣告进去。
        （也可以用 /32 静态路由，六条，但拓扑一变就得改）

  坑 2：next-hop-local 配在 eBGP 邻居上 → 0 best
  --------------------------------------------------------------
  现象：五对邻居全 Established，AR4 那边已经能通，
        AR1 却是 2 available / 0 best / 0 selected，
        Original nexthop 还是 10.0.24.4 / 10.0.34.4。
  真相：命令被加到了 peer 10.0.24.4（eBGP）上。
        eBGP 本来就会把下一跳改成自己，加这条等于空转；
        真正要加的是两条 iBGP 邻居。
  判断：看 Original nexthop。如果它不是本机可达的地址，
        就是这个问题。
  修法：undo peer 10.0.24.4 next-hop-local
        peer 1.1.1.1 next-hop-local
        peer 3.3.3.3 next-hop-local

  坑 3：undo network 在 OSPF 进程视图敲 → 报错
  --------------------------------------------------------------
  现象：[Huawei-ospf-1] 里敲 undo network 10.0.24.0 0.0.0.255，
        提示 Error: Unrecognized command found at '^' position，
        而且 '^' 指在掩码前面，看着像掩码写错了。
  真相：network 命令属于 area 视图，不在进程视图。
        '^' 只是"从这里开始匹配不上"，不代表那一处写错。
  修法：先 area 0，再 undo network。

  坑 4：reset ospf process 在 OSPF 视图敲 → 报错
  --------------------------------------------------------------
  现象：[Huawei-ospf-1] 里敲 reset ospf process 报错。
  真相：reset 系列命令是用户视图的命令。
  修法：quit 两次回到 <Huawei> 再敲。
  通用规律：
        display ...  任何视图都能用
        reset ...    用户视图 <Huawei>
        save、ping、tracert  用户视图
        看提示符是 <> 还是 [] 就能判断自己在哪一层。

  坑 5：改 OSPF router-id 后不生效
  --------------------------------------------------------------
  现象：配置里写着 router-id 2.2.2.2，
        display ospf peer brief 却显示 Router ID 10.0.12.2。
  真相：Router ID 在进程启动那一刻就定了，
        之后改只写进配置，不改变正在运行的值。
  修法：reset ospf process（会断一下邻居重建）。
        本题三台的 Router ID 互不冲突，不改也不影响结果。

  坑 6：route-policy 名字写错 → 静默失效
  --------------------------------------------------------------
  现象：定义了 route-policy CD，但 BGP 里引用的是 BCD。
        设备不报错，配置照样保存，路由照样能通，
        只是 MED 一直是默认值 0。
  真相：引用了不存在的策略，策略静默不生效。
  判断：去 display current-configuration configuration
        route-policy 里核对名字，一个字母都不能差。
        再去邻居上看 MED 值对不对。
  修法：undo peer 10.0.34.3 route-policy BCD export
        peer 10.0.34.3 route-policy CD export

  坑 7：ping 不带 -a → 100% 丢包（不是路由问题）
  --------------------------------------------------------------
  现象：AR1 上 ping 192.168.2.10 全部超时，
        ping -a 192.168.1.254 192.168.2.10 就通了。
  真相：路由器 ping 默认用出接口地址当源地址。
        去 192.168.2.10 走 G0/0/1，源地址就是 10.0.12.1。
        请求能到，但 AR4 没有 10.0.12.0/24 的回程路由
        （那是 AS 65001 内部网段，从没通告给 BGP），
        回应包被丢掉，所以看到 100% 丢包。
  判断：ping 不通但路由表里有路，先看源地址。
  修法：-a 指定一个 BGP 通告过的地址，或者直接从 PC 上测。

  坑 8：eBGP 加 connect-interface LoopBack0 → 连不上
  --------------------------------------------------------------
  真相：eBGP 默认 TTL=1，而且环回地址在 AS 65002 那边
        没有任何协议通告，AR2 根本到不了 4.4.4.4。
        加了 connect 之后源地址变成 2.2.2.2，AR4 也不认识。
  修法：eBGP 一律直连地址，不要 connect-interface。

【十、思考题答案要点】
================================================================

  1. Local_Pref 和 MED 分别在哪个范围传播？一个管出去，
     一个管进来？

  Local_Pref：只在同一个 AS 内传播（iBGP 带，eBGP 丢）。
              管的是"我自己的流量从哪个出口出去"。
              越大越优先，默认 100。

  MED：      跨 AS 传，但只传给直接相邻的那个 AS，
              不再往下传（可选非传递属性）。
              管的是"建议邻居从哪个入口进来"。
              越小越优先，默认 0。

  一句话：Local_Pref 是内部商量，MED 是对外建议，
  所以 Local_Pref 的优先级天然高于 MED。

  2. AR2 和 AR3 都是 65001 的边界，外面看到的 AS_PATH
     会不会有两条不同长度？为什么？

  不会，两条完全一样，都是 65001，长度都是 1。

  因为 AS_PATH 记录的是"AS 号"，不是"路由器"。
  AS_PATH 的规则是：谁把路由发到另一个 AS，
  谁就在前面加上自己所属的 AS 号。
  AR2 和 AR3 都属于 65001，加的是同一个数字。

  实测证据（AR4 上）：
    From 10.0.24.2：AS-path 65001
    From 10.0.34.3：AS-path 65001
  只有 AR2、AR3 分属不同 AS 时，长度才会不同。

  3. 为什么 BGP 默认会在 Router ID 这么"不相干"的东西上
     做最后一轮比较？

  因为前面所有能衡量"路径好坏"的指标都打平了，
  必须有一个"确定、唯一、全网一致"的兜底规则。

  如果让设备随机选、或者都选，两台边界路由器可能各选各的，
  去程和回程走不同的出口，甚至形成环路——那比选错更糟。

  用 Router ID 至少保证：同一个 AS 内所有路由器
  对同一条前缀得出同一个结论。

  所以 Router ID 不是用来衡量路径好坏的，
  它只是用来"消除平局"的。

  4. network 和 import-route 都能把路由放进 BGP，
     为什么更推荐 network？

  network：只把路由表里已经存在、掩码精确匹配的路由
           放进 BGP，origin = igp，抓多少条由你一条条点。
  import-route：把某个协议的全部路由灌进来，
           origin = incomplete，容易把不该通告的明细、
           私网段甚至环路风险一起带出去。

  工程上选 network，因为精准、可审计、
  出问题能追到具体那一行。
